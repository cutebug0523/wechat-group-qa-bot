# Ubuntu 方案和 Windows 方案的区别

> 结论先说：**要 7×24 无人值守挂群，选 Ubuntu**。Windows 的现成轮子更多、上手更快，但它离不开一个「真开着的桌面」，而且新版微信的现成库还不成熟。
>
> 下文里「实测」的是我们自己在 Ubuntu 24.04 上跑出来的；Windows 部分没有在本项目里跑过，来自公开资料，会标出处。

## 一张表看完

| | **Ubuntu（本项目）** | **Windows** |
|---|---|---|
| 客户端 | 官方 Linux 微信 4.x（Qt 界面） | 官方 Windows 微信 3.9 / 4.x |
| 读界面的接口 | AT-SPI（Linux 无障碍标准，走 D-Bus） | UI Automation（UIA，Windows 无障碍标准） |
| 现成的库 | 基本没有，本项目自己写 | 多：wxauto（3.9）、wxauto4 / wxautox4（4.x） |
| 新版微信支持 | 实测 Linux 4.x 能读到消息列表、输入框、右键菜单 | wxauto4、wxautox4 目前只写明支持 4.0.5，还在测试阶段；wxautox4 要授权[^wxauto4] |
| 要不要显示器 | 不要：Xvfb 虚拟屏，SSH 进去就能管 | 要一个活着的交互桌面：远程桌面一断开，窗口就不再绘制，UI 自动化跟着失灵，得另想办法让会话一直挂着 |
| 抢不抢鼠标 | 不抢：虚拟屏有自己的鼠标键盘 | 抢：自动化动的就是这台机器的鼠标，人在用就会打架 |
| 多开 | 每个实例一块虚拟屏、一套 D-Bus、一个 HOME，互不干扰 | 一般得开虚拟机 |
| 微信更新 | 解压到目录里跑，版本自己定，不会被强制升级打断 | 客户端会提示、强制升级，界面一变库就失效 |
| 成本 | 一台旧电脑或几十块一个月的云主机，系统免费 | 要 Windows 授权；云上 Windows 主机更贵 |
| 封号风险 | 低：官方客户端 + 无障碍接口 + 键盘鼠标 | 同样低，**前提是只用 UIA 这类库**。Windows 上 Hook / 注入框架很多，一不小心就用成了高风险方案 |
| 上手难度 | 高：要懂 Xvfb、AT-SPI、D-Bus，界面结构得自己摸 | 低：pip 装个库，几十行 Python 就能收发 |

## 关键差别展开说

### 1. 读消息：AT-SPI 和 UIA 是同一种东西，生态天差地别

两边本质一样，都是操作系统给读屏软件留的无障碍接口。Qt 写的程序在 Linux 上走 AT-SPI，在 Windows 上走 UIA / MSAA[^qt]。

- **Linux**：Qt 默认不开无障碍，要设 `QT_LINUX_ACCESSIBILITY_ALWAYS_ON=1`，再起一个 AT-SPI 总线（见 `start.sh`）[^qt]。打开以后能拿到：
  - 每个群窗口里一个叫「消息」的列表，每条有正文和坐标，图片是「图片」二字；
  - 输入框；
  - 右键菜单项，「@ 某人」就在里面。
- **但是没有发言人。** 列表条目里只有正文，所以本项目要截图、用 OCR 读昵称，再用头像指纹兜底。这是 Linux 方案最费劲的地方。
- **条目会被复用。** 滚出屏幕的旧条目会被拿去放新消息，同一个对象路径前后放过不同的消息。判断「这条读没读过」不能只看路径加正文，本项目改成只认最近两轮，再看位置有没有跳变。
- **Windows**：wxauto 这类库把这些脏活都包好了，`GetAllMessage()` 直接拿到「谁说了什么」。但它们跟着具体微信版本走，4.x 还在追[^wxauto4]。

### 2. 无人值守：Linux 的决定性优势

UI 自动化要求窗口真的被画出来。

- **Linux**：Xvfb 本身就是一块一直在画的屏幕。机器放在柜子里，SSH 进去就能截图、扫码、看日志。本项目就是这么挂着三个群的。
- **Windows**：远程桌面一断开，会话进入锁屏，窗口不再绘制，自动化就失灵。常见的绕法有：
  - 把会话切到控制台；
  - 开虚拟机；
  - 一直不断开远程桌面。

  这些都不太省心。

### 3. 封号风险：两边都能做到低，Windows 更容易「走歪」

决定风险的是**怎么接**，不是哪个系统：

- **Hook / 注入**（往微信进程注代码）：历次封号潮的重灾区。公开报道里，大规模封禁时「几乎所有基于 hook 或逆向协议的框架都中招了」[^ban]。这类框架绝大多数只有 Windows 版。
- **协议逆向**（iPad / Mac 协议）：服务器看到的是非官方客户端，是另一种风险。网上说它「风险较低」的文章，多半是卖协议服务的[^ban]。
- **UI 自动化**（本项目、wxauto）：服务器看到的就是正常登录的官方客户端，风险最低。

Windows 上现成的 Hook 框架太多，搜教程很容易掉进去。Linux 上基本只有 UI 自动化这一条路，反而不会走歪。

### 4. 企业微信

- Linux 上没有企业微信原生版，只有 Wine 套 Windows 版（deepin-wine 那套）。Wine 里的程序不走 AT-SPI，本项目读不到，只能整屏截图加 OCR，等于重写一遍。
- Windows 上企业微信是原生的，UIA 能读到多少要另测。
- 普通微信小号进企业微信的外部群没问题，本项目就盯着一个这样的群。

## 怎么选

- **要长期挂着、不想有人守着、要多开**：Ubuntu，用本项目。
- **只是自己电脑上玩玩、愿意跟着微信版本调**：Windows + wxauto 系列最快。注意只用 UIA 的库，别碰 Hook。
- **两边都不建议**：Hook 注入、协议逆向。

[^qt]: Qt 文档：QAccessible，支持 MSAA、macOS Accessibility 和 Unix/X11 AT-SPI；Linux 上可用 `QT_LINUX_ACCESSIBILITY_ALWAYS_ON` 强制开启。<https://doc.qt.io/qt-6.8/zh/qaccessible.html>
[^wxauto4]: wxauto4（cluic/wxauto4 的 Gitee 镜像），写明「目前仅适用于微信 4.0.5 版本客户端」：<https://gitee.com/LyaQanYi/wxauto4>；wxautox4，标明 4.0 Beta、需要授权：<https://pypi.org/project/wxautox4/>
[^ban]: CSDN 文章，讲一次大规模封禁里 hook / 逆向框架几乎全部中招：<https://damodev.csdn.net/6a4382e3662f9a54cb86d221.html>；选型对比（Web 协议、Hook、RPA）：<https://damodev.csdn.net/6a59ef6a10ee7a33f28e7715.html>
